## 产品一句话

Clove 是给摄影师在 iPhone、iPad 和 iPhone Duo 上用的原位选片应用。你对着 SD 卡、外置硬盘或 Files 里的文件夹看图、打星、打色标、标拒绝。RAW 照片组的星级和色标写进 XMP 旁路文件；单独的 JPEG/HIF 的新标记只保存在 Clove。拒绝片在你确认后被移进 `_Rejected` 文件夹，不会被删除。原片内容从不修改。回家后用 Lightroom、Capture One 或 Photo Mechanic 接着做，它们只会看到留下来的照片，以及 RAW 照片组的 XMP 星级和色标。

它不是相册管理器，不是云备份，也不是社交或调色工具。对标对象是第三方应用 [AI Photo Culling — PhotoPicker](https://apps.apple.com/us/app/ai-photo-culling-photopicker/id661470243)，不是系统自带的照片选择器。

策略：手动选片体验和 XMP 写得准，优先于 AI。首发的智能功能只做相似组，而且可以关掉。

## 给谁用，用来干什么

目标用户是要在外出或回程路上完成第一轮挑选的摄影师，主要拍 RAW、RAW+JPEG 或 RAW+HIF，也包括 RAW+JPEG+HIF 照片组。他们把照片放在 SD 卡、外置 SSD 或 Files 能打开的文件夹里，需要尽快浏览、检查是否合焦，然后留下能被桌面软件读懂的标记。

主要工作：

1. 打开或重新打开一个文件夹（含 `DCIM/100XXXXX` 这类子目录），而不是把照片导入应用或系统图库。
2. 在网格里快刷，进入大图查焦。
3. 用手势、按钮或键盘打星、打色标、标拒绝。
4. 对连拍按组挑：组内对比，留下最好的一两张，其余拒绝。
5. 一键把拒绝片移进 `_Rejected` 文件夹。
6. 在 Lightroom、Capture One 或 Photo Mechanic 里读到同样的星级和色标，继续后期。

## 主路径

打开文件夹或从「最近打开」重开 → 网格浏览、筛选、排序 → 进入详情查焦并翻图 → 打星或色标（RAW 组写 XMP，单独的 JPEG/HIF 存在 Clove），或标拒绝（存在 Clove） → 按相似组挑连拍 → 执行「整理拒绝片」 → 离开后重新打开，标记还在，原片内容没有被改动。

## 首发明确不做

- Pick 旗（由星级取代）
- 系统照片图库入口（主入口或次要入口），以及「选一批照片进入临时会话、不写 XMP」的流程
- 把收藏或标记写回系统照片图库
- 相册管理、关键词管理、云备份、CloudKit、备份或同步向导
- 社交、分享流
- 打开或写回 Lightroom Classic catalog
- 自建目录，或把已选照片连同 XMP 拷到新文件夹（可作后续优先项，但不在首发）
- 删除原片、导出成片、视频主流程。把拒绝片移进 `_Rejected` 不是删除。
- 双图对比（已推迟）
- 调色、自动对焦点叠加
- AI 推荐最佳张、低质与糊片建议（推到 1.1）
- 手动拆分或合并相似组、用户自建组（拆分推到 1.1）
- 分组灵敏度设置
- Duo 叠加模式、Duo 半折专属布局（推到 1.1）
- 闭眼和表情分析、自然语言选片、联网云端 AI、任何由 AI 自动写入或覆盖标记的功能
- 自研 RAW 解码或 demosaic

## 各屏与状态

以下行为以产品与 UI 结论及上方各次修订为准。与 `design/handoff/` 设计交付包不一致时，按交付包执行。

### 入口：打开与最近打开

- 主操作是「打开文件夹…」，走 Files / SD / 外置盘。
- 「最近打开」列出路径摘要、介质类型、张数、上次时间。点一项即用已记住的位置重开。
- 不提供系统照片图库入口。
- 稿面有搜索框。产品定稿没有单独锁定搜索最近打开的行为，不列为 P0。

### 扫描范围

- 递归扫描打开目录下的所有子目录。SD 卡的 `DCIM/100XXXXX`、`101XXXXX` 等目录合在一起显示。
- 跳过拒绝片文件夹（默认 `_Rejected`）。
- 同一目录下按不区分大小写的同名规则匹配：RAW+JPEG、RAW+HIF、RAW+JPEG+HIF 各只占一格，以 RAW 为主。伴随文件只作参考，永不修改；星级和色标使用 RAW 共用的旁路文件。
- 支持单独的 RAW 和单独的 JPEG。没有 RAW 时优先以 JPEG 为主，其次 HIF。单独的 HIF 和 iPhone HEIC 在系统能预览时显示，完整支持延后。没有 RAW 的 JPEG+HIF 不受支持，接受通用规则的处理结果。
- 打不开或不支持的文件，单独显示可见状态，不能用空白图冒充已经加载。

### 网格

- iPhone：三列。iPad：五列，左侧栏用于导航和筛选。
- 单元格叠加拒绝旗、星级、色点。带 JPEG 和/或 HIF 伴随文件的 RAW 照片组有角标提示。
- 排序：默认按拍摄时间（读到亚秒），没有则依次用文件创建时间、修改时间。不能先显示临时的文件名顺序。使用后备文件时间的照片不参与分组。仍可选择按文件名排序。
- 顶部筛选：全部、未标记、拒绝、N 星及以上。
- 相似组的显示方式：
  - 「展开」（默认）：显示每一张，同组照片用蓝框圈在一起，标出张数。
  - 「折叠」：每组只显示一格封面加张数，点进去就是组视图。
  - 默认展开的原因：分组在后台逐步细化，折叠视图的格子会增减。无论哪种方式，分组细化都不能让用户正在看的那张照片位置跳走。
- 从网格可进入详情，也可进入相似组。
- 长按进入多选，再批量写入。
- 网格里不设双击操作，以免拖慢单击进入详情。

### 详情与标记

- 全宽预览。双指缩放查焦。双击画面中部，以点按处为中心放大到 100%，再双击回到全图。
- 左右边缘点按翻到上一张或下一张，放大时同样可用。边缘区域只识别单击，不等待双击，翻图不延迟。
- 当前标记必须一眼能看到，不能被手指挡住。详情使用顶部标记提示（星级、拒绝、色标）。iPad 使用右侧标记轨。这是为了避开竞品里「底栏状态被手挡住」的问题。
- 底片条标出当前张，可横滑跳转。
- 稿面另有文件名一类信息。具体展示哪些拍摄参数未锁定，不列为 P0。

标记规则：

| 控件 | 行为 |
| --- | --- |
| 星级 0 到 5 | 在星级条上点选某一级，再点同一级清零。只显示已启用的星级。 |
| 色标 | 默认红、黄、绿、蓝、紫，外加清除。设置里可开启扩展色（橙、粉，对应 Capture One）。写入 XMP 时使用固定英文名，不随系统语言变化。 |
| 拒绝 | 单独的开关。与星级互不影响：标拒绝时原有星级保留。拒绝不等于删除。 |
| 撤销 | 接入系统撤销机制：工具栏撤销按钮、外接键盘 ⌘Z、iOS 三指撤销手势都可用。自动前进之后撤销，画面回到被撤销的那一张。「拒绝 N 张未标记」和整理拒绝片也能撤销，各算一步。 |
| 保存状态 | XMP 写入使用「写入中…」「已写入」「写入失败」，读回确认后才显示「已写入」。拒绝片移动确认后才显示成功。单独的 JPEG/HIF 标记确认存入应用后显示「仅保存在 Clove」。失败后提供重试。 |

### 多选批量写入

在网格长按进入多选，对选中的照片一次写入星级、色标或拒绝。成功与失败按张计算。部分成功时，已写上的保持已写上，失败的保持未写入，并允许只重试失败的那些。

### 手势与键盘

详情页手势：

| 状态 | 操作 | 效果 |
| --- | --- | --- |
| 全图 | 慢速上下拖动 | 从当前星级开始，上拖升档，下拖降档，依次经过启用的星级、0 和 −1。可在同一次手势中越过起点反向。 |
| 全图 | 快速下滑 | 短距离清零至 0，继续下滑至 −1（拒绝）。反向先回 0，向上越过起点取消。快速上滑按慢拖处理。 |
| 全图 | 左右滑、边缘点按 | 翻图 |
| 全图 | 双击画面中部 | 以点按处为中心放大到 100% |
| 放大 | 单指拖动 | 平移画面。上下滑打标在放大时停用。 |
| 放大 | 边缘点按 | 翻图 |
| 放大 | 双击 | 回到全图 |
| 任意 | 双指缩放 | 缩放 |
| 任意 | 三指系统手势、⌘Z | 撤销 |

上滑按幅度打星：

- 慢拖从当前星级开始，每 60pt 一档，经过启用的星级、0（清零）和 −1（拒绝）。双向每跨一档给一次轻触觉。未打星时下拖一档拒绝；已拒绝时上拖依次经过 0 和最低启用星级。
- 用最初约 100ms 的平均竖直速度一次决定慢拖或快速下滑，初值阈值为向下 500pt/s，中途不切换。快速上滑按慢拖处理；不足 100ms 就松手时按已有的初始样本判定。
- 快速下滑只有起始值、0 和 −1 三个停点：60pt 清零并给中等触觉，180pt 拒绝并给更重的触觉。反向从拒绝回到 0，向上越过起点恢复原值。未打星时经过 0 不改值；已拒绝时下滑不再降低，上拖走慢拖阶梯。不按住等待拒绝。
- 星级条在触摸起点旁保持不动；清零显示空星级条，到拒绝立即显示 ✕。只显示图形，阶段名称由 VoiceOver 朗读。
- 松手写入预览值，只记一次撤销，不改色标，没有惯性。回到起始值或系统取消都不写入。
- 距离、速度窗口和阈值、轻/中/重触觉强度均为具名初值，在 iPhone 上调试。

启用哪些星级（设置）：

- 用户选择允许使用的星级，默认 1 到 5 全部启用。
- 慢拖相对于当前值，依次经过启用的星级。例如启用 1、3、5 星时，从 1 上拖依次是 3、5，从 3 下拖依次是 1、0、拒绝。当前值若已禁用，仍是起点，回到起点恢复它；其余禁用星级跳过。
- 星级条和键盘也只接受已启用的星级。
- 这个设置只影响录入，不影响显示和筛选。其他软件已写下的 4 星、5 星照常显示，不会被改写。

外接键盘（iPad 优先，iPhone 接上键盘时同样生效）：

| 键 | 效果 |
| --- | --- |
| `0` 到 `5` | 打星（`0` 清零） |
| `6` `7` `8` `9` | 红、黄、绿、蓝色标（与 Lightroom 一致） |
| `↑` | 升到下一个已启用的星级 |
| `↓` | 拒绝 |
| `←` `→` | 翻图 |
| `⌘Z` | 撤销 |

自动前进（设置）：

- 打完标记后：停在当前张 / 下一张（默认）/ 下一张未标记的。
- 触发前进的标记：星级和拒绝默认触发，色标默认不触发。
- 打完后先停约 0.3 秒，让用户看到标记已生效，再前进。
- 在组视图里，自动前进到组内下一张待定的照片。组完成后的行为见「组内选片」。

手势相关设置：手势总开关、启用哪些星级、自动前进、触发前进的标记、双击行为（缩放（默认）/ 关闭）、翻图时保持缩放（组内默认开，普通详情默认关）。

### 相似组

首发智能功能只有相似组，目标是把连拍和重复构图归在一起。它只帮用户分组，不替用户写任何标记。

分组方式：

1. 按机型分开，有机身序列号时再加上序列号，然后按拍摄时间排序，读到亚秒。没有序列号时退回机型。两台同机型机身在同一时刻拍同一场景不受支持，不为此增加工作、界面或设置。
2. 按时间间隔切段：相邻两张间隔小于 2 秒的归入同一段。这是待真实样本检查的初值，不是首发准确率承诺。这一步只读拍摄元数据，打开目录后很快就能先显示出来。
3. 段内按画面相似度再切：在设备上对 400 px 嵌入预览计算 Vision 特征（特征版本 2），相邻距离大于 0.5 时断开。Vision 不可用时采用 dHash，阈值为 12 bit；没有可用特征时断开。这一步在后台运行，完成后细化分组。

规则：

- 少于 2 张的不算一组。没有拍摄时间的文件不参与分组。
- 分组结果只缓存在 Clove 里，不写进 XMP。
- 界面显示分析进度或「已分析」。「再跑一次」始终可以点。
- 用户可以关掉相似组。关掉后入口和网格蓝框都隐藏，打开、浏览和手动打标不受影响。
- 不提供分组灵敏度设置，先用实测校准过的默认值。
- 不对分组准确率做任何数字承诺。

### 组内选片

一组连拍可能有几十张，区别只在焦点、表情和动作瞬间。组视图围绕「对比细节、缩小范围、一键收尾」设计。

布局：

- iPhone：上方大图，下方本组底片条。
- iPad 和 Duo 内屏：大图加侧栏组内网格。
- 每张都显示星级或拒绝状态。顶部显示「待定 N / 共 M」。待定指既没有星级也没有拒绝的照片。

对比与淘汰：

- 同步缩放：在组内放大到某个位置后，翻到下一张时保持同样的缩放倍数和位置。组内始终开启，不提供开关。
- 被拒绝的照片在底片条上变暗。「只看待定」开关打开后，翻图跳过已拒绝和已打星的照片。
- 打完标记后自动前进到组内下一张待定的照片。

一键收尾：

| 操作 | 效果 |
| --- | --- |
| 拒绝 N 张未标记 | 把组内没有星级、没有色标、也没有拒绝的照片标为拒绝。组内任意一张打星或加色标后出现。要保留一张、拒绝其余，先给它打星，再用这个操作。 |

- 已有星级或色标的照片永远不会被这个操作拒绝。
- 这个操作按批量写入的规则处理成功与失败，并且可以作为一步撤销。

组完成：

- 定义：组内每张都已打星或已拒绝，或者用户执行了一键收尾。
- 设置「组完成后」：停在本组 / 自动进入下一组（默认）。跳到下一组时跳过已完成的组。

### 整理拒绝片

拒绝只服务于选片。整理之后，桌面软件里只剩留下的照片，不需要知道哪些被拒绝过。

- 触发：用户手动点「整理拒绝片」，不自动执行。可以在目录内任意时候执行。
- 拒绝状态按文件夹身份和文件保存在 Clove，保留到移动。移动本身是持久结果；尚未移动的拒绝状态不跨重装或设备保留。
- 确认：弹出确认，写明要移动多少张、包含 JPEG 和/或 HIF 伴随文件及 XMP、原片不会被删除。
- 移动前保留：确认里可以查看这些拒绝片，点一张即保留，再点取消保留。保留只是暂存：点「移动」之前不写入任何东西，关掉确认则放弃这些保留。点「移动」后，保留的照片清除拒绝（星级和色标不变），其余照片移动。
- 目标：打开目录下的 `_Rejected/`，文件夹名可在设置里修改。保留原来的子目录结构，例如 `DCIM/100XXXXX/IMG_0001.CR3` 移到 `_Rejected/DCIM/100XXXXX/IMG_0001.CR3`。
- 照片组作为一个整体移动：主文件、所有 JPEG 和/或 HIF 伴随文件、对应的 XMP。
- 只在同一个卷上做移动，不做「复制再删除」。
- 目标位置已有同名文件时加后缀，绝不覆盖。
- 按张计算成功与失败。部分失败时，已移动的保持已移动，失败的留在原处，可以只重试失败的。
- 只读位置不能整理，沿用「只能看」的提示。
- 移走后，这些照片从网格消失，之后扫描也跳过 `_Rejected`。
- 撤销：移动之后，撤销把文件移回原来的路径，并恢复它们以及确认里保留过的照片的拒绝状态，算一步撤销。原路径已被其他文件占用时绝不覆盖：那一组留在 `_Rejected` 并报告出来。撤销历史之外的还原不做首发：用户自己把文件移回，由于 XMP 只包含星级和色标，这些照片的拒绝状态不会恢复。
- 设置里可以关闭整理功能。关闭后拒绝仍可用于筛选，只是不提供移动。

## 标记如何落盘

磁盘上的 XMP 是 RAW 照片组已保存星级和色标的事实来源。拒绝和单独的 JPEG/HIF 的新标记存在 Clove 的应用存储中。「已写入」指已确认的 XMP 写入和拒绝片移动结果；单独文件的标记使用「仅保存在 Clove」。

1. 显示已保存标记前，RAW 组先读已有 XMP，单独的 JPEG/HIF 先读内嵌星级和色标。拒绝和 Clove 内保存的标记从应用存储读取。
2. 首发永不修改原片图像内容。RAW 组只写 XMP 旁路文件，其 JPEG/HIF 伴随文件永不修改。
3. 旁路文件按「同名、换扩展名」命名，例如 `IMG_0001.CR3` 对应 `IMG_0001.xmp`。RAW+JPEG、RAW+HIF、RAW+JPEG+HIF 组各共用一份。复用已有 `.xmp`/`.XMP` 的实际大小写。`IMG_0001.CR3.xmp` 这类追加扩展名的文件或多份候选包视为歧义，绝不另建第二份。桌面软件检查仍需完成。
4. 星级写入标准星级字段，色标写入标准色标字段。
5. 拒绝只存在 Clove 中，按文件夹身份和文件记录，保留到移动进 `_Rejected`。永不把拒绝写入 XMP。Clove 的 XMP 拒绝字段、「拒绝时同时写 Rating −1」设置及保存原有星级的机制均已移除。尚未移动的拒绝状态不跨重装或设备保留。
6. 单独的 JPEG/HIF（含能预览的 iPhone HEIC）不建旁路文件。读取已有内嵌星级和色标；新标记存在 Clove，并明确显示「仅保存在 Clove」。JPEG 文件内写入是后续功能，HIF/HEIC 文件内写入仍不做。单独的 DNG 属于 RAW，使用旁路文件。
7. 按每次修改实际使用的存储确认结果。XMP 星级和色标读回一致后才显示「已写入」；拒绝片移动确认后才显示成功。单独文件的标记确认存入应用后显示「仅保存在 Clove」。写入中、失败、尚未确认的修改都不能显示成功。
8. 写失败时保留用户刚才做的选择，供重试。重试成功前，不把它当成已经保存。
9. 尽量保全文件里原有的、Clove 并不认识的其他信息，避免为了写一个星级而丢掉别的软件留下的数据。
10. 色标在 XMP 里写固定英文名，不随界面语言变化。默认 5 色是 Red、Yellow、Green、Blue、Purple。

### 失败与恢复

下面的用户可见句子是建议文案，不是已批准文案。含义需要准确。只读和空间不足必须分开说，不能并成一句让人猜。数量用占位，不写死某次看到的张数。

| 情况 | 建议文案 | 用户可以做什么 | 界面不得出现的状态 |
| --- | --- | --- | --- |
| 单张写入失败 | 这张的标记没写上。要再试一次吗？ | 再试一次；取消 | 先显示已写入，再悄悄变回未保存 |
| 这个文件夹的访问权限没了 | 这个文件夹的访问权限没了。请重新打开一次。 | 重新打开该文件夹 | 继续显示能写，实际写不进去 |
| 找不到记住的位置 | 找不到这个位置了。请从「打开」重新选一次。 | 从「打开文件夹」再选 | 点「最近打开」后没有任何说明 |
| 位置只读，或存储本身不允许写入 | 这个位置现在只能看，不能写入标记。 | 取消，或在可写位置重新打开 | 和「空间不够」混成一句 |
| 位置没有足够空间 | 这个位置空间不够，标记写不进去。 | 腾出空间后再试 | 和「只能看」混成一句 |
| 外置盘在使用中断开 | 磁盘断开了。请重新接上，再打开这个文件夹。 | 接上后再打开 | 仍显示正在写入或已经写好 |
| 批量写入部分失败 | 写好了 N 张，还有 M 张没写上。 | 重试没写上的；取消 | 把整批显示成全部成功或全部失败 |
| 整理拒绝片部分失败 | 已移动 N 张，还有 M 张没移动。 | 重试没移动的；取消 | 把没移动的照片从网格里隐藏 |
| 用户关闭页面或离开目录时，还有未确认的写入 | 还有标记没写完。 | 等写完再离开；仍然离开 | 离开后把未确认的修改显示成已保存 |

如果用户在写入未完成时仍然离开，未确认成功的修改不能当作已保存。下次打开时读取 RAW 星级和色标的实际 XMP、单独文件的内嵌标记，以及已确认的 Clove 存储状态。

## 智能分组与手工标记

手工标记是唯一的事实。相似组只负责分组。

- 分组和「再跑一次」都不会写入或改动任何标记。
- 组内的一键收尾是用户主动执行的操作，并且永远不会拒绝已有星级或色标的照片。
- 用户关掉相似组后，主路径完整可用。
- 不把准确率、召回率或「接近竞品」写成首发承诺。

## 浅色、深色与易用

- 所有主屏同时有浅色和深色，并跟随系统外观。Duo 与其他设备用同一套结构，不另做深色皮肤。
- 使用系统导航栏、工具栏、列表、按钮和系统色，以便跟随系统对比度和常规辅助功能。
- 按幅度打星对部分用户不方便，星级条和键盘必须能完成所有标记操作，并支持 VoiceOver。
- 不在本文承诺具体对比度数值或尚未写明的朗读文案。需要补的是各状态和报错的准确、非技术说法，见上表。

## 打开哪些文件

首要输入是相机文件：单独的 RAW、RAW+JPEG、RAW+HIF、RAW+JPEG+HIF、单独的 JPEG。有 RAW（含 DNG）时以 RAW 为主，同一目录下同名的 JPEG/HIF 是参考伴随文件。没有 RAW 时优先以 JPEG 为主，其次 HIF。单独的 HIF 和 iPhone HEIC 在系统能预览时显示，完整支持延后，不做文件内写入或额外格式工作。没有 RAW 的 JPEG+HIF 不受支持，按通用规则处理。HEIF 扩展名包括 `.HEIC`、`.HEIF` 和 `.HIF`。首发不做自研 RAW 解码。

可以依据的公开事实，而不是 Clove 自己测过的保证名单：

- 网格和详情预览应优先走系统图像能力。工程结论建议网格先用嵌入预览，详情在需要看清时再做完整 RAW 处理。双击放大到 100% 时，先放大嵌入预览，必要时再解码完整 RAW。见[工程调研来源](https://app.notion.com/p/41237873fb548107bd96d0f6838b1200)。
- Apple 公布过 iOS 相机 RAW 支持机型，工程调研引用的是 [iOS 18 支持页（页面标注 2025-07）](https://support.apple.com/en-us/120534)。名单随系统更新变化。未列入的机型，Apple 仍为 DNG 提供基础支持。部分机型只支持未压缩、无损或单拍 RAW。
- 系统能生成预览时，Clove 打开上面支持的相机文件组；单独的 HIF 和 iPhone HEIC 是延后完整支持的功能，能显示则显示。具体能打开哪家相机的哪一种压缩格式，以用户设备上的系统支持为准。本文不另列一份保证机型表。
- DNG（如 iPhone ProRAW、徕卡、宾得）在显示和旁路写入时都属于 RAW。更广泛的 iPhone 文件工作等到照片图库支持时再做。见「标记如何落盘」第 6 条。
- 打不开、或不支持的压缩格式，必须有可见说明，不能用空白图冒充已经加载。
- [G1 的起始性能目标](decisions/G1-technical-approach.md#starting-performance-targets-iphone-for-m3-and-q3)用于 M3 和 Q3 的工程检查。数据来自一台使用本机存储的 iPhone，卡和 iPad 检查后重新评估，不是首发承诺或目录规模上限。

首发不提供系统照片图库入口。若以后要加，也不能变成只在临时会话里看图、不写 XMP 的流程，需要单独决定。

## 隐私与离线

- 主路径是对着用户自己的文件夹工作。RAW 的星级和色标写在该文件夹的旁路文件里。拒绝和单独的 JPEG/HIF 的新标记保存在 Clove 的应用存储中。
- 相似组分析在设备上完成。首发不做联网云端 AI，也不做 CloudKit 或备份同步。
- 无网络时，用户必须仍能打开有权限的文件夹、浏览、打标、写入 XMP 和整理拒绝片。
- 旧工程结论未发现 siftapp 依赖应用云服务。Clove 首发也不引入把原片上传到自家服务器这件事。
- 本文不代替正式隐私政策文本。

## 工程约束（不是产品范围本身）

这些条目约束怎么做，但不增加上面没有的产品功能。

- 交付形态是新的原生 iOS / iPadOS 应用，最低系统 iOS 18。旧的 Flutter 仓库 [siftapp](https://github.com/mimiqdev/siftapp) 只作参考，不做代码迁移，也不做旧用户或旧项目的过渡。新仓库是 [cloveapp](https://github.com/mimiqdev/cloveapp)。
- 产品已锁定「不做自研 RAW demosaic」。预览和解码优先使用系统图像能力，是工程建议，并已写进产品页给工程的说明。是否在 Apple 目标上完全去掉自有 RAW 图像代码，要等真实样本验证后再定，不因此改产品范围。
- 相似组使用设备上的视觉特征计算图像相似度，输入用嵌入预览。1.1 的最佳张推荐可考虑系统的美学评分能力。
- 记住文件夹位置、在外置盘上读写和移动文件，属于平台文件权限问题。对用户只表现为「最近打开」和上面的失败恢复，不要把内部权限术语写进界面。
- 整理拒绝片必须是同卷移动，每个文件的成功与失败单独确认。
- Duo 布局按实际可用空间变化，不要按设备类型写死两套互不相通的界面。半折时避开折缝。
- 保存成功必须能按文件、按这一次修改确认。不能在尚未确认时把界面画成已保存。

### 待实测核实

[G1 决策](decisions/G1-technical-approach.md)已确定元数据写入方案和分组起始阈值。剩余桌面软件检查必须在 C3 宣告完成前执行。[#29](https://github.com/mimiqdev/cloveapp/issues/29) 跟踪剩余外置介质、iPad 和桌面软件检查。可移动介质不在 MVP 关键路径上；外置介质检查不阻塞进度，方便时优先用 CFexpress Type A USB 读卡器。iOS 把它视为和 SSD 一样的外置盘；SD 卡不是负责人的工作流程。G2 在 iPhone 17 Pro Max 上使用 Files 能打开的任意文件夹，包括本机存储，或手边有读卡器时使用该读卡器。[#18](https://github.com/mimiqdev/cloveapp/issues/18) 的 Duo 实测仍未完成。结果可调整实现和起始目标；范围变化需交回产品负责人决定。

- Lightroom 读取 JPEG 内嵌元数据，Photo Mechanic 把 JPEG 星级写入文件内，Capture One 是否为单独的 JPEG 使用旁路文件仍不明确。因此 G1 决定单独的 JPEG/HIF 的新标记只存在 Clove；DNG 仍属 RAW，使用旁路文件。
- 核实三家桌面软件对替换扩展名的旁路文件，以及含 JPEG/HIF 伴随文件的 RAW 照片组共用一份旁路文件的实际处理。
- Capture One 扩展色（橙、粉）在 XMP 中的英文名，以及 Lightroom 和 Photo Mechanic 读到这些值时的表现。
- 非英文界面的 Lightroom 是否把色标名本地化，导致固定英文名对不上。若是，需要在帮助中说明如何切回默认色标集。
- 元数据写入可行性已确定：JPEG 可无损拼接元数据包，延后到 C7；ImageIO 写入 HIF/HEIC 会丢数据，DNG 没有写入器。因此 DNG 使用旁路文件。
- 分组起始值已确定：2 秒和 Vision 距离 0.5。每档打星的滑动距离仍待调整。
