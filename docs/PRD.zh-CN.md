## 产品一句话

Clove 是给摄影师在 iPhone、iPad 和 iPhone Duo 上用的原位选片应用。你对着 SD 卡、外置硬盘或 Files 里的文件夹看图、打标记。星级、Pick、拒绝和色标只写入 XMP 旁路文件，原片不动。回家后用 Lightroom、Capture One 或 Photo Mechanic 接着做。

它不是相册管理器，不是云备份，也不是社交或调色工具。对标对象是第三方应用 [AI Photo Culling — PhotoPicker](https://apps.apple.com/us/app/ai-photo-culling-photopicker/id661470243)，不是系统自带的照片选择器。

策略：手动选片体验和 XMP 写得准，优先于 AI 准不准。AI 可以关掉。

## 给谁用，用来干什么

目标用户是要在外出或回程路上完成第一轮挑选的摄影师。他们把照片放在 SD 卡、外置 SSD 或 Files 能打开的文件夹里，需要尽快浏览、检查是否合焦，然后留下能被桌面软件读懂的标记。

主要工作：

1. 打开或重新打开一个文件夹，而不是把照片导入应用或系统图库。
2. 在网格里快刷，必要时进入大图检查焦点。
3. 打上星级、Pick、拒绝或色标。这些标记只写进 XMP。
4. 查看相似组和低质、糊片建议，决定要不要采用。建议不能改掉已经亲手打过的标记。
5. 合上电脑后，在 Lightroom、Capture One 或 Photo Mechanic 里读到同样的标记，继续后期。

## 主路径

打开文件夹或从「最近打开」重开 → 网格浏览并筛选 → 进入详情查焦并翻图 → 打星 / Pick / 拒绝 / 色标，写入 XMP → 需要时查看智能组并决定是否采用建议 → 离开后重新打开，标记还在，原片没有被改动。

## 首发明确不做

- 把系统照片图库当成主工作区，或做成「选一批照片进入临时会话、不写 XMP」的流程
- 把收藏或标记写回系统照片图库
- 相册管理、关键词管理、云备份、CloudKit、备份或同步向导
- 社交、分享流
- 打开或写回 Lightroom Classic catalog
- 自建目录，或把已选照片连同 XMP 拷到新文件夹（可作后续优先项，但不在首发）
- 删除原片、导出成片、视频主流程
- 双图对比（已推迟）
- 调色、自动对焦点叠加
- 自然语言选片、联网云端 AI、一键让 AI 覆盖已有星级或色标
- 自研 RAW 解码或 demosaic

Figma 智能组屏里出现了「手动组」样例行。产品定稿没有把用户自建组列为首发，本 PRD 不把它列入 P0。

## 各屏与状态

以下行为以产品与 UI 结论为准。Figma 页 `Culling UI — Native (canonical)` 是当前稿面，含 20 个浅色/深色框：iPhone 的入口、网格、详情、智能组；iPad 的网格加侧栏、详情加右侧标记轨；Duo 的外屏紧凑、内屏默认 Split、半折、非默认 Overlay。稿面不等于已批准视觉。

### 入口：打开与最近打开

- 主操作是「打开文件夹…」，走 Files / SD / 外置盘。
- 「最近打开」列出路径摘要、介质类型、张数、上次时间。点一项即用已记住的位置重开。
- 不要把系统照片图库做成首发主入口。
- 稿面有搜索框。产品定稿没有单独锁定搜索最近打开的行为，不列为 P0。

### 网格

- iPhone：三列。iPad：五列，左侧栏用于导航和筛选。
- 单元格叠加 Pick 或拒绝旗、星级、色点。相似组用蓝框和张数提示。低质或糊片用较弱的角标提示。
- 顶部筛选：全部、Pick、拒绝、三星及以上。可以后续加「未标记」，但不阻塞首发。
- 从网格可进入详情，也可进入智能组（顶栏「相似组 N」或对应入口）。
- 长按进入多选，再批量写 XMP。

### 详情与标记

- 全宽预览。双指缩放查焦。左右边缘点按翻到上一张或下一张，放大时同样可用。
- 当前标记必须一眼能看到，不能被手指挡住。详情使用顶部标记提示（星、Pick 或拒绝、色标）。iPad 使用右侧标记轨。这是为了避开竞品里「底栏状态被手挡住」的问题。
- 底片条标出当前张，可横滑跳转。
- 稿面另有文件名一类信息。具体展示哪些拍摄参数未锁定，不列为 P0。

标记规则：

| 控件 | 行为 |
| --- | --- |
| 星级 0 到 5 | 点选某一级。再点同一级可清零。 |
| Pick / 未标记 / 拒绝 | 三态互斥。拒绝不等于删除原片。 |
| 色标 | 红、橙、黄、绿、蓝、紫，外加清除。写入 XMP 时使用固定的英文 Lightroom 名称，不随系统语言变化。已写出的名称是 Red、Yellow、Green、Blue、Purple。橙色对应的英文名待与 Lightroom 实际字段核对，不在本文发明一个名字。 |
| 保存状态 | 「写入中…」「已写入」「写入失败」。失败后提供重试。只有确认成功才能显示「已写入」。 |

### 多选批量写入

在网格长按进入多选，对选中的照片一次写入星级、Pick、拒绝或色标。成功与失败按张计算。部分成功时，已写上的保持已写上，失败的保持未写入，并允许只重试失败的那些。

### 手势与键盘

默认手势可以在设置里改：

- 上滑：Pick。下滑：拒绝。
- 左右滑动或边缘点按：上一张或下一张。标记手势和翻图手势分区，降低误触。
- 双指缩放：查焦。缩放时仍可用边缘点按翻图。

首发建议提供、采用合理默认即可的设置：

- 打完标记后是否自动前进到下一张
- 手势映射（旗、星，或关闭手势）

外接键盘（iPad 优先，iPhone 接上键盘时同样生效）：`0` 到 `5` 打星，上方向键 Pick，下方向键拒绝，左右方向键翻图。色标键位不在首发锁定。

### 智能组

- 打开目录后自动跑一遍。界面显示进度或「已分析」。
- 「再跑一次」始终可以点。
- 相似组以组卡呈现，并标出建议的最佳张。「采用建议」之后才写 XMP。
- 低质或糊片以列表建议呈现。用户可以忽略，或自己标拒绝。应用不会自动把这些照片标成拒绝。
- 不覆盖用户已有的星级、Pick、拒绝或色标。不能提供一个默认打开的「覆盖已有标记」。
- 用户可以关闭 AI。关闭后入口隐藏，打开、浏览和手动打标不受影响。
- 系统低于 iOS 18 时隐藏 AI 入口。主流程仍可用。

首发智能组范围是相似组（用特征距离找连拍一类重复）和低质、糊片建议。闭眼、表情分析不做首发。不承诺对标竞品的「一键 AI 出片」。本文不对 AI 准确率做任何数字承诺。

### iPhone、iPad 与 iPhone Duo

| 设备 | 首发行为 |
| --- | --- |
| iPhone 单屏 | 三列网格。详情单页完成查焦和打标。 |
| iPad | 五列网格加左侧栏。详情使用右侧标记轨。双图对比不做首发，但单图闭环必须通。 |
| iPhone Duo 外屏 | 按紧凑布局设计：入口或三列网格，再进入详情。不另做一套信息结构。 |
| iPhone Duo 内屏 | 按较宽布局扩展，默认同时显示网格和详情（宽时左右、高时上下）。叠加模式必须能用，但打开目录后不默认使用它。 |
| iPhone Duo 半折 | 网格和详情各在一侧。筛选、标记和底栏只落在其中一侧，不得跨过折缝。网格优先使用偶数列，便于对半切开。 |

从外屏翻到内屏、半折或改窗口大小时，用户不能丢失当前文件夹、当前照片、筛选条件、多选和正在显示的写入状态。

## 标记如何落盘

对用户来说，磁盘上的 XMP 旁路文件才是标记的事实来源。界面上的「已写入」只能表示这件事已经在磁盘上完成。

1. 打开目录时先读已有 XMP，再显示星级、旗标和色标。
2. 只写 XMP 旁路文件，不改原片内容。
3. 用户确认要采用的智能组建议，才写入对应标记。自动分析结果本身不是已保存的标记。
4. 只有写入确认成功后，才把该张该次修改记为已保存。写入中、失败、尚未确认的修改，都不能显示成「已写入」。
5. 写失败时保留用户刚才做的选择，供重试。重试成功前，不把它当成已经保存。
6. 尽量保全文件里原有的、Clove 并不认识的其他信息，避免为了写一个星级而丢掉别的软件留下的数据。
7. 色标在 XMP 里写固定英文 Lightroom 名，不随界面语言变化。

### 失败与恢复

下面的用户可见句子是建议文案，不是已批准文案。含义需要准确。只读和空间不足必须分开说，不能并成一句让人猜。数量用占位，不写死某次看到的张数。

| 情况 | 建议文案 | 用户可以做什么 | 界面不得出现的状态 |
| --- | --- | --- | --- |
| 单张写入失败 | 这张的标记没写上。要再试一次吗？ | 再试一次；取消 | 先显示已写入，再悄悄变回未保存 |
| 这个文件夹的访问权限没了 | 这个文件夹的访问权限没了。请重新打开一次。 | 重新打开该文件夹 | 继续显示能写，实际写不进去 |
| 找不到记住的位置 | 找不到这个位置了。请从「打开」重新选一次。 | 从「打开文件夹」再选 | 点「最近打开」后没有任何说明 |
| 位置只读，或存储本身不允许写入 | 这个位置现在只能看，不能写入标记。 | 取消，或在可写位置重新打开 | 和「空间不够」混成一句 |
| 位置没有足够空间 | 这个位置空间不够，标记写不进去。 | 腾出空间后再试 | 和「只能看」混成一句 |
| 外置盘在使用中断开 | 磁盘断开了。请重新接上，再打开这个文件夹。 | 接上后再打开 | 仍显示正在写入或已经写好 |
| 批量写入部分失败 | 写好了 N 张，还有 M 张没写上。 | 重试没写上的；取消 | 把整批显示成全部成功或全部失败 |
| 用户关闭页面或离开目录时，还有未确认的写入 | 还有标记没写完。 | 等写完再离开；仍然离开 | 离开后把未确认的修改显示成已保存 |

如果用户在写入未完成时仍然离开，未确认成功的修改不能当作已保存。下次打开以磁盘上实际读到的 XMP 为准。

## AI 建议与手工标记

手工标记是唯一的事实。智能组只提出建议。

- 打开目录后自动分析，用户也可以手动再跑。
- 采用建议才会写 XMP。
- 已有星级、Pick、拒绝或色标时，分析或再跑都不能改掉这些标记。
- 用户关掉 AI 后，主路径完整可用。
- 不把准确率、召回率或「接近竞品」写成首发承诺。

## 浅色、深色与易用

- 所有主屏同时有浅色和深色，并跟随系统外观。Duo 与其他设备用同一套结构，不另做深色皮肤。
- 使用系统导航栏、工具栏、列表、按钮和系统色，以便跟随系统对比度和常规辅助功能。
- 不在本文承诺具体对比度数值或尚未写明的朗读文案。需要补的是各状态和报错的准确、非技术说法，见上表。

## 打开哪些文件

产品锁定的范围是：打开文件夹后扫描 JPEG、HEIC 和主流 RAW。首发不做自研 RAW 解码。

可以依据的公开事实，而不是 Clove 自己测过的保证名单：

- 网格和详情预览应优先走系统图像能力。工程结论建议网格先用嵌入预览，详情在需要看清时再做完整 RAW 处理。见[工程调研来源](https://app.notion.com/p/41237873fb548107bd96d0f6838b1200)。
- Apple 公布过 iOS 相机 RAW 支持机型，工程调研引用的是 [iOS 18 支持页（页面标注 2025-07）](https://support.apple.com/en-us/120534)。名单随系统更新变化。未列入的机型，Apple 仍为 DNG 提供基础支持。部分机型只支持未压缩、无损或单拍 RAW。
- 因此，Clove 的产品承诺是：打开系统能够生成预览的 JPEG、HEIC 和主流 RAW。具体能打开哪家相机的哪一种压缩格式，以用户设备上的系统支持为准。本文不另列一份保证机型表。
- 打不开、或不支持的压缩格式，必须有可见说明，不能用空白图冒充已经加载。
- 典型目录有多大、预览要多快、详情解码要多快，都还没有写入产品定稿的数字。任何耗时或张数目标都只能标成待实测，不能写成首发承诺。

系统照片选择器如果以后作为次要入口出现，也不能变成只在临时会话里看图、不写 XMP 的流程。按已锁定的产品页，把系统相册库当作选片入口属于后续，不列入本 PRD 的 P0。

## 隐私与离线

- 主路径是对着用户自己的文件夹工作。标记写在该文件夹的 XMP 旁路文件里。
- 智能组分析在设备上完成。首发不做联网云端 AI，也不做 CloudKit 或备份同步。
- 无网络时，用户必须仍能打开有权限的文件夹、浏览、打标并写入 XMP。
- 旧工程结论未发现 siftapp 依赖应用云服务。Clove 首发也不引入把原片上传到自家服务器这件事。
- 本文不代替正式隐私政策文本。

| P0-03 | 在含有嵌入预览的 RAW 目录中滚动网格，缩略图能用于浏览。不能打开的文件有明确状态，而不是一块空白却当作已加载。 |

| P0-06 | 事先用 Lightroom、Capture One 或 Photo Mechanic 写过的星、旗、色标，在 Clove 打开后能看见。Clove 写回后，上述软件能读到。文件里原有的其他 XMP 信息在写入后仍在。 |
| P0-07 | 写入过程中显示「写入中…」。成功后才变为「已写入」。人为让写入失败后，显示失败并可以重试，界面从不把这次修改显示成已保存。 |
| P0-08 | 长按多选若干张并批量打 Pick。让其中一部分失败后，提示「写好了 N 张，还有 M 张没写上」。已成功的保持已写入，失败的可以单独再试。 |
| P0-09 | 打开目录后智能组自行开始分析，随后「再跑一次」可用。对已经手标过的照片采用建议后，原有手标仍在。关闭 AI 后入口消失，打开、浏览和手动打标仍可用。在低于 iOS 18 的设备上，AI 入口不可见，主流程仍可用。 |
| P0-10 | 在 iPhone 和 iPad 上都能走完：打开目录 → 网格 → 详情打标 → 退出再打开，标记仍在。 |
| P0-11 | 在 Duo 外屏能打开目录并打标。展开到内屏后，仍是同一个目录、同一张图和同一组标记，默认看到网格和详情并排。可以改成叠加，但新打开目录时不是叠加。半折时筛选、标记和底栏都不跨过折缝。 |
| P0-12 | 系统在浅色和深色之间切换后，入口、网格、详情、智能组和 Duo 各姿态都跟着变。 |

补充互操作验收：同一文件夹可以与 Photo Mechanic 或 Lightroom 交替使用，双方写下的星、旗和色标都能被对方读到。

## 工程约束（不是产品范围本身）

这些条目约束怎么做，但不增加上面没有的产品功能。

- 交付形态是新的原生 iOS / iPadOS 应用。旧的 Flutter 仓库 [siftapp](https://github.com/mimiqdev/siftapp) 只作参考，不盲目迁移。新仓库是 [cloveapp](https://github.com/mimiqdev/cloveapp)。
- 产品已锁定「不做自研 RAW demosaic」。预览和解码优先使用系统图像能力，是工程建议，并已写进产品页给工程的说明。是否在 Apple 目标上完全去掉自有 RAW 图像代码，要等真实样本验证后再定，不因此改产品范围。
- 智能组使用设备上的视觉分析。产品页对应到美学评分和特征距离；闭眼与表情不做首发。
- 记住文件夹位置、在外置盘上读写，属于平台文件权限问题。对用户只表现为「最近打开」和上面的失败恢复，不要把内部权限术语写进界面。
- Duo 布局按实际可用空间变化，不要按设备类型写死两套互不相通的界面。半折时避开折缝。工程调研把较完整的 Duo 体验指向较新的系统 SDK。那是实现目标，不是已经拍板的最低系统版本。
- 保存成功必须能按文件、按这一次修改确认。不能在尚未确认时把界面画成已保存。

## 尚未拍板

只列出会改变首发承诺、且来源里还没有决议的事项。

- 最低系统版本。已定的是：低于 iOS 18 时隐藏 AI，主流程仍应可用。主流程究竟支持到多低的系统，尚未决定。工程曾把 17 及以上当作验证候选，又把更完整的 Duo 体验指向更新的 SDK。这两点都不是最低版本决议。
- 收费方式。来源中没有免费、一次性付费或订阅的结论。
- 是否以及何时停止维护旧的 Flutter siftapp，以及旧用户和旧项目除 XMP 互认之外还要怎样过渡。
- 系统相册作为次要入口是否进入首发。锁死的产品页把它列为后续；同时已经排除「临时会话、不写 XMP」这种做法。本 PRD 不把它列入 P0。
- 色标里「橙」写入 XMP 时所用的英文名，需要与 Lightroom 实际字段核对后再定。
- 视觉稿尚未见到认可记录。

不在首发承诺里出现、因而也不能写成验收数字的事项：性能耗时、AI 准确率、保证支持的相机或存储品牌名单、目录规模上限。若以后要写目标，先实测，再单独批准。
